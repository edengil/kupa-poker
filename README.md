# קופה — פוקר · גרסת ענן

אותה אפליקציה, עם התחברות Google בשבילך ולינק צפייה בשביל הקבוצה.

- `/` — האפליקציה המלאה. דורשת התחברות Google, ורק אתה נכנס.
- `/g/<slug>` — לינק ציבורי לקריאה בלבד. בלי חשבון, בלי התחברות, ומתעדכן לבד.

בצפייה בלבד מוצגים רק הטאבים **טבלה** ו**שחקנים**. הטאבים לייב, הזנה וערבים
פשוט לא קיימים שם, וכל ניסיון כתיבה נעצר גם בקוד וגם ב-RLS של מסד הנתונים.
כשיש משחק פעיל, מופיע מעליהם פאנל **משחק עכשיו** עם המצב הנוכחי של השולחן.

---

## מה השתנה מהקובץ המקורי

הלוגיקה לא נגעה. ההמרה נגעה בשתי נקודות בלבד:

1. **שכבת האחסון.** `components/PokerApp.jsx` מייבא עכשיו את `store` מ-`lib/store`
   במקום להגדיר אותו מעל `localStorage`. החוזה זהה — `await store.get(key)` ו-
   `await store.set(key, value)` — ולכן 8 מקומות הקריאה בקוד לא השתנו.
2. **מצב קריאה בלבד.** `App` מקבל `readOnly`, `commit` יוצא מוקדם, ו-`TabBar`
   מסנן את הטאבים שכותבים.

הסנכרון בזמן אמת נוסף סביב האפליקציה ולא בתוכה — ראה למטה.

## הקמה

> **פעם ראשונה? פתח את `מדריך-התקנה.md`** — שם הכל מפורק לצעדים עם מה
> ללחוץ ומה אמור להופיע. הסעיף כאן הוא תקציר למי שכבר מכיר את הכלים.

### 1. Supabase

1. פרויקט חדש ב-[supabase.com](https://supabase.com).
2. **SQL Editor** → הדבק את `supabase/schema.sql` → Run.
3. **Authentication → Providers → Google** → הפעל.
   צריך Client ID ו-Client Secret מ-Google Cloud Console
   (APIs & Services → Credentials → OAuth client ID → Web application).
   ב-*Authorized redirect URIs* בגוגל, הדבק את ה-Callback URL ש-Supabase מציג במסך.
4. **Project Settings → API** — משם ה-URL וה-anon key.

### 2. מקומית

```bash
cp .env.local.example .env.local   # ומלא את שלושת הערכים
npm install
npm run dev
```

### 3. Vercel

Import מ-GitHub, ואז **Settings → Environment Variables**:

| שם | ערך |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | ה-URL מ-Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ה-anon key |
| `NEXT_PUBLIC_SITE_URL` | הדומיין הסופי, למשל `https://kupa.vercel.app` |

אחרי הדיפלוי, שתי פעולות שקל לשכוח:

- ב-Supabase → **Authentication → URL Configuration**: הגדר את *Site URL* לדומיין,
  והוסף `https://<הדומיין>/auth/callback` ל-*Redirect URLs*.
- אם הדומיין משתנה, `NEXT_PUBLIC_SITE_URL` צריך להתעדכן איתו.

## העברת הנתונים הקיימים

האפליקציה הישנה כבר יודעת לייצא ולייבא JSON, אז אין צורך בכלום מעבר לזה:

1. פתח את הגרסה הישנה במכשיר שבו הנתונים יושבים.
2. הגדרות → **גיבוי** → ייצוא. נשמר קובץ `kupa-poker-<תאריך>.json`.
3. היכנס לגרסה החדשה עם Google, ובאותו מסך גיבוי — ייבוא של אותו קובץ.

הייבוא עובר דרך `commit`, כך שהוא נכתב ישירות ל-Supabase. משם הלינק הציבורי כבר מציג אותו.

## איך האבטחה עובדת

הטבלה סגורה מאחורי RLS: רק `auth.uid() = owner_id` נוגע בשורה. אף אחד אחר לא קורא
ולא כותב, גם לא דרך ה-API הישיר.

הלינק הציבורי לא עוקף את זה. הוא עובר בפונקציה `public_group(slug)` שמוגדרת
`security definer` ומחזירה ארבע עמודות בלבד — `name`, `data`, `live`,
`updated_at` — לפי slug אחד. אין דרך למשוך את רשימת הקבוצות, ואין דרך להגיע
ל-`owner_id` או ל-slug של קבוצה אחרת.

מה שכן כדאי לדעת: ה-slug הוא מפתח הגישה. מי שיש לו את הלינק רואה את הטבלה. אם
לינק דלף, `update groups set slug = '<חדש>' where id = '<id>'` ב-SQL Editor מבטל
את הישן מיד.

## סנכרון בזמן אמת

הצופים לא צריכים לרענן. כשאתה מזין ערב או מזיז משחק חי, המסך שלהם מתעדכן לבד.

**למה Broadcast ולא Postgres Changes.** Postgres Changes מכבד RLS, ולצופה אנונימי
אין ולא תהיה גישה לטבלת `groups`. כדי שזה יעבוד היה צריך לפתוח את הטבלה לקריאה
ציבורית — בדיוק מה שהסכימה נועדה למנוע.

לכן מה שעובר בערוץ `group:<slug>` הוא ping ריק, בלי נתונים. מי שמקבל אותו קורא
מחדש דרך `public_group(slug)` — אותה פונקציה מוגבלת שהוא כבר משתמש בה. גם אם
מישהו ישדר ping מזויף, כל מה שיקרה זה קריאה מיותרת אחת.

**איך זה מרגיש בצד הצופה.** `PokerApp` נטען פעם אחת ולא מקשיב לשינויים מבחוץ, אז
רענון שלו נעשה בהחלפת `key`. זה קורה רק כשהטבלה עצמה השתנתה — משחק חי זורם דרך
`LiveNow` בלי לגעת בו, אחרת כל עדכון היה מחזיר את הצופה לטאב הראשון. בנוסף, חזרה
למסך אחרי שהדפדפן היה ברקע מפעילה קריאה משלימה.

**למה `LiveNow` הוא רכיב נפרד.** `LiveTab` מחזיק עשר יחידות state ונטען פעם אחת,
כך שהוא לא בנוי להתעדכן מבחוץ, והוא מלא בפקדי עריכה שלצופה אין מה לעשות איתם.
`LiveNow` רק מציג, ומשתמש באותו חישוב בדיוק: `cashout / chipsPerShekel - buyin`.

## הערות תפעול

**כתיבה מרוכזת.** האפליקציה שומרת את כל ה-DB כאובייקט אחד בכל פעולה. `lib/store.js`
מחזיק debounce של 700ms כדי לא להציף את השרת במשחק חי, ו-`flushStore()` נקרא
לפני יציאה מהדף וביציאה מהחשבון.

**הפרויקט לא נרדם.** Supabase משהה פרויקטים חינמיים אחרי 7 ימים בלי פעילות —
מלכודת אמיתית לקבוצה שמשחקת פעם בחודש. `vercel.json` מגדיר cron שבועי שפונה
ל-`/api/keep-alive`, ושם שאילתה זולה אחת מאפסת את השעון.

**Realtime לא דורש הגדרה.** ערוצי Broadcast עובדים עם ה-anon key כברירת מחדל,
בלי להוסיף טבלאות ל-replication ובלי לגעת בהגדרות הפרויקט.

**קבוצה אחת לחשבון.** `OwnerApp` לוקח את השורה הראשונה שלך או יוצר אחת. אם תרצה
כמה קבוצות בעתיד, זה כבר נתמך בסכימה — צריך רק בורר בממשק.
